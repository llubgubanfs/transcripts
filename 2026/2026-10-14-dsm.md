**Vic's git practice talk (Cebuano/English)**
- One commit per PR where possible: easier rollback, easier cherry-picking when features are isolated per client or release, clean linear history, simpler review. Details belong in the PR description [06:26–09:49].
- Put the ticket number first in commit messages (e.g. GP123 ...), so commits trace back to tickets years later and to non-technical readers who only reference ticket numbers. This is a suggestion; opting in is up to each person, but he highly recommends it in preparation for client work [10:10–14:23].
